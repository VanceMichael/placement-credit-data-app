# 人才对接成果的归因与补贴收口

业务资料均为合成记录。表头字段及跨表引用见 `fixtures/format.json`。

## 数据说明

接触 T 是一次报名或咨询。follow_consent 是活动允许跟踪的标志，tracking 按触点登记月底联系结果。employment 结束日包含当日，确认日在开始日之后不表示入职更晚。同一岗位伙伴关系见 policy.scope，阶段天数以首次实际到岗为起点，受认可的跨法人间隔不重复算在岗天数。
推荐以岗位匹配、在入职前提名且入职落于保护期内为候选，同时受内外部争议记录约束。重叠提名待决时整项暂挂，决定 shared 按两份 share，withdrawn 撤销该项请求。未出现决议的明确单项按该机构标准份额；交叉文件中的期为月度，首期第 1–30 日。小组发布门槛以有效观察的不同人计。
资金优先使用对应园区专属额度，余额可使用当期 shared。committed 与 paid 占用实际额度。确认的负向调整从实际责任机构的当期占额冲抵，冲抵不得超过已有对应支出，暂提调整另列敞口。

CSV 使用 UTF-8、逗号分隔，无引号与内嵌换行。未提供的字段是空字符串，作为关系值的 `-` 表示不适用。多值字段用竖线分隔，数值和日期单位见业务约定。

## 资料检查

使用 Node.js 22.23.4，依赖仅为 Node.js 标准库。运行 `npm ci --ignore-scripts --offline` 准备工作区。

运行 `npm run check:materials` 检查合成交接资料的字段与记录引用。运行 `npm test` 检查交接资料的读取、校验与业务口径。运行 `npm run report` 按当前资料生成月底结账报表。

## 业务口径

引擎（`src/engine.mjs`）从同一批资料生成快照，报表、园区查询和公开比较都从这份快照读取，因此同一份资料可重复得到同样的结果。

**身份。** 跨活动只用 `identities` 中 `status=confirmed` 的关联连接，`pending` 弱匹配保留为待核实候选，不并入身份，也不参与成效或结算。结账后新确认的关联在下次运行时生效。

**任职。** 只有已核验（`verified_day` 不晚于统计时点）的 `employment` 才可用。被 `supersedes` 指向的记录视为更正后的替代；撤回后续记录时，原记录重新可用。按人、岗位与时间形成任职链：跨法人只在同一 `policy.scope` 且间隔不超过 `max_gap`、岗位不变时承接，断档或范围外转岗重新起算。在岗天数按区间并集计，跨法人重叠的过渡日不重复计。

**活动成效。** 按“人在统计窗口内首次符合的任职”计，每人最多计一次。窗口内最早的任职若有多个活动的接触，归入最早的可跟踪接触所在活动；其后活动只能看到该人由更早活动带来，不重复计成效。覆盖率的分母是该活动 `follow_consent=true` 的登记人数，联系不到的人仍留在分母里并单列。

**推荐归因。** 提名须岗位匹配、提名日不晚于到岗日、且到岗日落于保护期内。入职前已受理的争议决定最终权利：待决则整项暂挂；`shared` 按两份 `share` 折算，合计超过 1 时归一到一笔批准金额；`withdrawn` 撤销该请求；`primary` 归一家。无决议的明确单项按该机构标准份额。入职后受理的争议只记录在链上供复核，不推翻入职时形成的提名权。

**资金与结账。** 申请先过资格（有可核验任职且阶段已到观察期、未提前结束）、归因（机构有有效提名份额）和付款（金额不超过批准份额、同人同阶段只占一笔、额度足够）三层检查。专属额度优先，余额用当期 `shared`。同一人同阶段只有通过资格与归因的申请能占位，团队分摊按同一任职内各机构份额共占一笔；被挤掉的后续批次登记在 `displacements`，已确认款不因此从账上腾空。

**调整与敞口。** 已支付的负额调整从责任机构调整期占额冲抵，且不超过对应支出；未冲部分不从账上腾空。暂提调整只列敞口，不进入净额。逐人分期视图把已支付正额与确认调整按人按期对齐。财务汇总区分暂留资金（挂起申请、争议未决）、已确认却受阻的款项与真正可另拨的余额。

**园区查询与公开比较。** 各园区只能看到本园区申请，逐条标明阻塞在资格、归因还是付款环节，并按首要原因给出一个动作：等待观察期/额度、提交提名证据、补入职证明、核对同阶段唯一性，或对已结算款提交下一期调整。公开比较只发布有效观察不同人达到 `publish_minimum` 的分层指标；若只有一个分层被压住，总数可反推该组，因而总数一并压住。

**下一期调整。** 机构可对责任范围内的付款提交下一期拟返还（负额）或补发（正额）确认，不能落在已结账期。确认记录只登记依据与方向，需重新运行资料才会落入账表。复核后发现已支付款失去支撑时，引擎另生成下一期拟返还建议（`settlement.followUps`），同样需机构确认后才落账，原期净额不变。

**法人、园区与额度。** `employment.entity`（法人）与 `funds.scope`/结算机构（园区）是不同维度，资料中没有法人到园区的映射，因此不做名称对应：转岗分析按法人列出已占与可支持阶段，`capacityFor(personId, park)` 按园区列出本地专属与共享额度。

## 目录

- `src/tables.mjs`：CSV 读取、字段与引用校验。
- `src/identities.mjs`：已确认关联的身份归并。
- `src/employment.mjs`：可核验任职、跨法人承接与阶段节点。
- `src/attribution.mjs`：推荐折算、接触链与活动成效。
- `src/funding.mjs`：结账、调整、逐人分期与敞口。
- `src/queries.mjs`：园区查询与公开比较。
- `src/transfers.mjs`：跨法人转岗与园区额度承接。
- `src/adjustments.mjs`：下一期调整提交与分期对齐。
- `src/engine.mjs`：把以上部分组装成可重算快照。
- `tools/report.mjs`：月底结账报表。
